# v0.8.2 — 2026-11-10 (optional evidence on apply + moonlit review)

## Apply
- Evidence is optional on **Apply** as well as Accept. An explicit `accept`
  row is enough; `apply --accepted` and `POST /apply` pass the stored
  evidence through, including `""`.
- Older accepts that already have blank evidence apply without being
  rewritten and without a second accept.
- Direct apply with a non-empty evidence string is unchanged (actor + source).
- Blank evidence without a current accept is refused. Reverted, rejected,
  deferred, and never-accepted rows are not eligible for `apply --accepted`.
- The `SUPERSEDED` / append note omits `because …` when no source was given.
  Nothing invents a placeholder source (the dry-run no longer substitutes one).
- Unchanged gates: `apply_enabled`, kill switch, secret scan, char limit,
  `require_grounded_evidence`, snapshot, sha verify, MEMORY lock,
  compare-and-swap, stale-line refusal, same-line keep+retired refusal,
  append-only ledger.

## Dashboard
- `/oneiros` review is a moonlit reading surface: proposal cards, plain
  pending / accepted / applied (and rejected, deferred, rolled-back) states,
  optional evidence called out on Accept and Apply, and the same Accept,
  Accept with note, Accept all, Undo, and separate Apply actions.
- Accept all still sends only the pending ids in the current profile/day list
  (and the on-page filter). Undo appends `reverted` rows.
- Motion is short and turns off under `prefers-reduced-motion`. No extra
  network, model, or tracking calls.

## Deploy
Sync the plugin tree the dashboard already loads (`dream_cycle/apply.py`,
`dashboard/plugin_api.py`, `dashboard/dist/index.js`, `dashboard/dist/style.css`,
`plugin.yaml`, `dashboard/manifest.json`). The running process keeps the
previous code until that plugin is reloaded. Do not apply against live
memory as part of the sync; review fixtures stay on scratch profiles.
