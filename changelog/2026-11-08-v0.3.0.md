## v0.3.1 — 2026-11-08 safe-write guard (from an external review)
- apply and rollback hold Hermes' own `MEMORY.md.lock` (flock, same convention as hermes-agent
  `tools/memory_tool_store.py::_file_lock`), bounded wait (`memory_lock_timeout_s`, default 10 s) then refuse.
- Compare-and-swap: file sha re-checked immediately before the atomic write (and before a rollback
  restore); a change refuses with "file changed since read" and logs `apply-refused`.
- Edits only the proposal's own `line_nos` by default; `--all-lines` / `all_lines` opts in.
- Refuses when an edited line carries both `keep` and a retired value (two facts sharing a label).
- Proposals now store `file_sha256` and the cited `lines` text; apply refuses + logs stale proposals
  (cited line changed, or a pre-v0.3.1 stage without freshness fields). Unrelated edits elsewhere are fine.
- 10 new tests incl. a concurrent memory-tool write and a lock-ignoring writer (97 total).
