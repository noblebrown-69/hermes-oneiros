# v0.6.1 — 2026-11-09 (conversation-only corroboration)

## Fix — false positives from tool dumps and compaction
- Session corroboration (state.db) no longer treats `role=tool` messages
  (web_search / web_extract / browser / read_file dumps) as evidence.
- Compaction / prior-context summary handoffs (`[CONTEXT COMPACTION …]`,
  `[PRIOR CONTEXT …]`, demoted-at-compaction markers) are skipped even when
  they arrive as `role=user`.
- Config (safe defaults **ON**):
  - `session_corroboration.ignore_tool_messages`
  - `session_corroboration.ignore_compaction_messages`
  - `session_corroboration.require_user_evidence` — assistant text may be
    scanned, but a fresh value needs at least one user citation to propose.
- Default `grounding_roles` is now `["user", "assistant"]` (tool removed).

## Fix — distinct-service port pairs
- Memory-side "same label, multiple values" proposals are skipped when each
  value has a high-confidence service/host name and the names all differ
  (e.g. ``chat-svc.service`` `:8089` vs ``img-gen`` `:8093`).
- `skip_distinct_service_conflicts: true` by default. Ambiguous lines still
  propose as before (no silent drop).

## Tests / docs
- Regression tests for tool exclusion, compaction exclusion, and two-services.
- Receipts, apply, rollback, and read-only state.db access unchanged.
